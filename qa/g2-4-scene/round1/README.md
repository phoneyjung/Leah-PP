## บ้านยาม C · สิ่งที่เกิดขึ้น
1. Object Creator ที่ 192 ใส่รูปอ้างอิงได้ **1/1** และได้ภาพเดียว → หยุดตามกติกาแผน → **เจ้าของเลือก Creator + Style image**
2. รอบ 1 (Create image Pro · ภาพสไตล์ = เด็ก 192 · รูปอ้างอิง 1 = รูปทรงบ้าน · ปิด copy สีจากภาพสไตล์ · พรอมป์ v1.1 เปลี่ยนแค่คำเรียกรูปอ้างอิง): `img/c-hut-192.png` หน้าตาดี สีผ่าน (ΔE00 ≥ 13 จากทุกสีบ้าน/สัญญาณ) แต่ **ประตู 36×69 px** (แผน 64×100 · เด็ก 47×83) → `img/c-hut-vs-plan-3x.png`
3. **เจ้าของเลือกกดใหม่เน้นผนังสูง** (`prompt-c2.txt` · รูปอ้างอิง 2 = บ้านรอบ 1) → ประตู **40×70 px** · หลังคาชนขอบภาพ (bbox 0–191) · ไม่ได้เก็บไฟล์ (Chrome จับภาพไม่ได้ช่วงนั้น · ภาพอยู่ในคลัง PixelLab)
4. ข้อสังเกต: PixelLab วาดประตูสูงราว 40 % ของตัวบ้านทุกครั้ง (69/175 · 70/156) ไม่ทำตามตัวเลขในพรอมป์ → **เจ้าของเลือกบ้าน 256 px** (กว้าง 8 ช่อง) · รูปอ้างอิง `refs/ref256-*.png` (`tools/make_refs256.py`) · พรอมป์ `prompt-c3-256.txt` · รูปอ้างอิง 2 = บ้านรอบ 1 (เอาลุค)
   - ผล: หน้าตาเดียวกับรอบ 1 · ประตู 52×103 (103/256 = 40 % ตามที่คาด) · เด็กเข้าช่องประตูได้ · **ช่องประตูกว้างกว่าตัวเด็กแค่ 5 px → โค้ดต้องจัดตัวเข้ากลางประตูเสมอ** (เกณฑ์ QG-4 ข้อ 2 เขียนใหม่เป็น ≥ ตัวเด็ก + 4 px ถ้าเจ้าของรับ)
5. **ผังต้องแก้หลังได้บ้าน 256:** บ้านกว้าง 6 → 8 ช่อง ทับลัง/เชือก (9,7)(9,8)(10,8) · รัน `layout.py` ใหม่ก่อนออก `ASSET_SPEC_10`

## วิธีเอาภาพออกจาก PixelLab แบบพิกเซลตรง
คอนเทนเนอร์ของ Claude เข้าเว็บ PixelLab ไม่ได้ จึงวาดภาพในหน้าเว็บเป็นบล็อกขยาย (กรอบเขียว `#00FF00` · ช่องใส = `#FF00FF`) แล้วจับภาพแบบไม่บีบอัด แล้วถอดกลับด้วย `tools/decode_shot.py` · เทียบจำนวนพิกเซลทึบ + checksum กับค่าที่คำนวณในหน้าเว็บ: **6/6 ไฟล์ตรง (MATCH)** · Codex ดึงไฟล์ต้นฉบับผ่าน API ได้อีกทาง (tileset A `c7953387-0629-467b-b95a-586227be6d70` · B `9700da98-2874-46f2-b0ef-51f8763d345e`)
